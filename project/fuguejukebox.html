FUGUEJUKEBOX

STABLE  C:\Dev\FUGUEJUKEBOX · Python (scipy synthesis/effects, ffmpeg encoding); Next.js 14 / React 18 / TypeScript (browsing site, broken)

FUGUEJUKEBOX transforms the 50 emblem fugues of Maier's Atalanta Fugiens into 500 chiptune MP3s: 50 emblems times 10 variations (3 harmonic elaborations, 3 scale-run/improvisation variants, 4 digital-effect treatments -- reverb, vibrato, echo, chorus), synthesized as square waves via a Python/scipy pipeline. Verified directly on disk: exactly 500 MP3s and 500 companion WAVs exist, matching the project's own completion reports -- this half of the project is genuinely done.

The website half is where it stalls. Two divergent folders exist: FUGUEJUKEBOX-website (the original working Next.js copy, linked to a Vercel project but never under its own git control) and FugueJukebox-repo (a separate git-tracked copy pushed to github.com/t3dy/FugueJukebox, whose own DEPLOYMENT.md explicitly excludes all 500 MP3s from the push due to GitHub file-size limits). The audio path baked into the React component is a filesystem-relative path that never resolves under real HTTP serving. The claimed live URL, https://fuguejukebox.vercel.app, was checked directly and returns HTTP 404 -- the site is dead, contrary to the README's 'LIVE ON THE WEB!' claim. A duplicate ~140MB copy of all 500 MP3s also sits in FUGUEJUKEBOX/music/emblems/, serving no purpose.

Per workspace hosting policy this project has no business on Vercel at all -- it's fully static.

The project's two website copies are confirmed genuinely divergent, not identical mirrors under different names: a direct file comparison between `FUGUEJUKEBOX-website/app/layout.tsx` and `FugueJukebox-repo/website/app/layout.tsx` shows real content differences, even though the two READMEs read as byte-identical text. The working copy's stack is a conventional 2024-era Next.js setup -- React 18.3.1, Next.js 14.2.0, TypeScript 5.3.3, the `lucide-react` icon library, custom CSS rather than Tailwind, EB Garamond for body text and Inter for UI chrome, a dark navy palette (`#0f172a` background, `#f1f5f9` text, `#d4af37` gold accent) -- a deliberately period-appropriate, alchemical-manuscript-adjacent visual design let down entirely by the audio-path and deployment problems described above, not by any lack of front-end effort.

The synthesis pipeline's actual algorithm is more specific than "harmonic elaboration" and "scale runs" as category labels suggest. `generate_variations.py` reads its 50-fugue source data directly from `C:/Dev/EmblemRoguelike/assets/fugues.json` -- a live cross-project file reference, not a local copy -- and builds three harmonic variants by adding fixed-interval voices beneath or around the melody: Variation 1 ("Root Position") adds a major third and perfect fifth below each note; Variation 2 ("First Inversion") adds a minor third below and a major sixth above; Variation 3 ("Close Voicing") adds a whole step below and a minor third above. The three scale-run variants only decorate notes longer than one beat, splitting each into three equal sub-durations and inserting two connecting notes: Variation 4 ("Diatonic") steps through a fixed C-major scale set, Variation 5 ("Chromatic") approaches chromatically from above, and Variation 6 ("Arpeggio") leaps by fourths. The four effects variants carry real, specific DSP parameters rather than generic labels: Cathedral Reverb runs at 70% wet with a 2.5-second decay and early reflections enabled; Vibrato Wobble combines a 0.15-depth, 5.5Hz vibrato with a 0.1-depth, 3.0Hz tremolo; Echo Cascade uses 60% wet feedback with triplet delay taps at 0.375, 0.75 and 1.125 seconds; and Spacious Chorus layers all of the above (50% reverb at 1.8-second decay, 20% delay at 0.5 seconds, plus the vibrato and tremolo settings) into one combined treatment. The actual synthesis engine, despite the README describing it as Web Audio, is pure offline NumPy and scipy: a square wave is generated as the sign of a sine function, a triangle wave from an arcsine transform of a sine function, both at a 44,100Hz sample rate with a linear ADSR envelope (release ramping to 0.01 rather than fully to zero) and headroom scaling of 0.6 -- there is no browser-side synthesis anywhere in the actual rendering path, only in how the README describes it.

Verified disk usage is larger than the README's own estimate: the 500 MP3s total roughly 144MB, close to the README's claimed figure, but the accompanying 500 uncompressed WAV intermediates add another 1.6GB, bringing the real `emblems/` folder to 1.8GB total -- and the duplicate copy in `music/emblems/` is a full duplicate of both the MP3s and WAVs, also roughly 1.8GB, not merely the ~140MB of MP3s alone that earlier documentation estimated.
