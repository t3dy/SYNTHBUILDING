FUGUEJUKEBOX

STABLE  C:\Dev\FUGUEJUKEBOX · Python (scipy synthesis/effects, ffmpeg encoding); Next.js 14 / React 18 / TypeScript (browsing site, broken)

FUGUEJUKEBOX transforms the 50 emblem fugues of Maier's Atalanta Fugiens into 500 chiptune MP3s: 50 emblems times 10 variations (3 harmonic elaborations, 3 scale-run/improvisation variants, 4 digital-effect treatments -- reverb, vibrato, echo, chorus), synthesized as square waves via a Python/scipy pipeline. Verified directly on disk: exactly 500 MP3s and 500 companion WAVs exist, matching the project's own completion reports -- this half of the project is genuinely done.

The website half is where it stalls. Two divergent folders exist: FUGUEJUKEBOX-website (the original working Next.js copy, linked to a Vercel project but never under its own git control) and FugueJukebox-repo (a separate git-tracked copy pushed to github.com/t3dy/FugueJukebox, whose own DEPLOYMENT.md explicitly excludes all 500 MP3s from the push due to GitHub file-size limits). The audio path baked into the React component is a filesystem-relative path that never resolves under real HTTP serving. The claimed live URL, https://fuguejukebox.vercel.app, was checked directly and returns HTTP 404 -- the site is dead, contrary to the README's 'LIVE ON THE WEB!' claim. A duplicate ~140MB copy of all 500 MP3s also sits in FUGUEJUKEBOX/music/emblems/, serving no purpose.

Per workspace hosting policy this project has no business on Vercel at all -- it's fully static.

Stuck / next
Three-step fix: decide the canonical MP3 copy (delete the duplicate), get audio into a servable path (public/ folder or Git LFS), redeploy static to GitHub Pages instead of Vercel.
