Chipped On Bach

ACTIVE  C:\Dev\NSFRIPPER\scripts\bach_nes_mashup.py · Python (numpy, mido), REAPER JSFX (ReapNES synth family), ffmpeg

Chipped On Bach is not a separate synthesis engine -- it's NSFRIPPER's own extraction/synth pipeline pointed at classical MIDI instead of extracted game MIDI. bach_nes_mashup.py, bach_render_mashup.py, and build_bach_preview.py pair Bach MIDI files with NES instrument presets mined from real game soundtracks, each stage contributing a distinct pulse-duty-cycle character, and render the combination through the same ReapNES JSFX synth family used everywhere else in the project.

Two finished video artifacts sit at the C:\Dev root: Chipped_On_Bach_Preview.mp4 (70.6MB, 39 tracks, 1:12:36 total) and Chipped_on_Bach_Preview_less_glitchy.mp4 (39MB, a curated 4-track, 7:28 re-cut). Both carry .txt sidecars drafted as YouTube descriptions, confirming synthesis runs through the real NES Audio Processing Unit emulation via ReapNES JSFX, not a mockup. A BACH_MAP dictionary in the preview builder expands short filenames to full catalog titles with BWV numbers, ready to reuse if these are ever actually published.

NSFRIPPER's own wishlist (state/wishes.json, item WISH16) flags that roughly 117 Bach-fugue by game-palette REAPER projects were generated but most were never rendered to WAV, likely interrupted by a crash -- still open, marked low priority. This is genuinely low-effort follow-on work: the expensive generation step already ran; only the render pass is incomplete.

A path worth checking before reusing these scripts: build_bach_preview.py reads source WAVs from C:\Dev\NESMusicStudio\output\bach_mashups, the pre-rename project path -- and NESMusicStudio now also exists as a separate, currently active folder, so this hardcoded path should be re-verified rather than trusted blindly.

The pairing algorithm is meaningfully more sophisticated than a fixed 1:1 mapping between a Bach piece and a game palette: `bach_nes_mashup.py` (1,029 lines) builds the full cross-product of every available Bach (and, per the script's own scope, some Mozart and Beethoven) piece against every NES stage preset, then scores each resulting pair using a hardcoded mood-compatibility matrix keyed on descriptive tags -- a "dark" piece paired with an "eerie" stage scores highly (9 out of a stated scale), a "bright" piece against an "aggressive" stage scores lower (5) -- and a `--render-best` mode greedily selects the top-scoring pairs while capping repetition (no more than two renders per Bach piece, no more than three per NES stage), so the eventual track list is a curated, mood-matched selection rather than an arbitrary or exhaustive one. Instrument routing within each render is also automatic rather than manually assigned: MIDI channels are sorted by average pitch and note density into triangle (bass), pulse 1 (the busiest or lead line), pulse 2, and noise (reserved for MIDI channel 9, the conventional drum channel), inferred fresh from each source file rather than hand-mapped per piece.

A genuine discrepancy surfaced in a closer read of the actual preset data, worth flagging rather than smoothing over: `bach_nes_mashup.py`'s own `STAGE_PRESETS` table -- the actual source of the timbre palettes used in generation -- contains zero Metroid entries at all; the games actually represented are Castlevania (5 stage presets), Contra (4), Journey to Silius (5), Gradius (3), Ghosts 'n Goblins (1), and Bionic Commando (6), 24 presets in total. Yet both finished preview MP4s' track listings include pieces explicitly labeled "x Metroid," and the separate preview-description builder script carries a bare `Metroid` entry with no associated stage detail -- meaning the Metroid material heard in the finished previews was very likely generated through a different code path or preset source than the one this pass located, not fabricated, but not traceable to the specific script examined here either.

The BACH_MAP dictionary that expands short internal filenames into full catalog titles for YouTube descriptions is a real, populated table (roughly 35 entries), not a placeholder -- confirmed examples include `Fugue2` expanding to "Well-Tempered Clavier, Fugue No. 2 in C minor, BWV 847," `invent1` to "Two-Part Invention No. 1 in C major, BWV 772," `var3c1` to "Goldberg Variations, Variation 3 (Canon at the Unison), BWV 988," and `pre1` to "Cello Suite No. 1, Prelude in G major, BWV 1007." WISH16's recorded status in NSFRIPPER's own wishlist is, precisely, "blocked" rather than simply "open" -- its exact recorded description reads "Render WAVs for the 117 Bach fugue mashup REAPER projects," with the rationale "Fugues 1, 2, 5, 7 crossed with every CV1 and Contra palette exist as RPPs but have zero WAV files; likely interrupted by crash." The two finished preview artifacts have precise, confirmed sizes and durations: `Chipped_On_Bach_Preview.mp4` is 70,594,367 bytes (about 67.3 MiB) and runs 1 hour, 12 minutes and 36 seconds across 39 tracks, opening with "Goldberg Variations, BWV 988 x Metroid" and carrying several informal editorial notes in its own track list such as "[good harmonies noisy pulse]" and "[filthiest lead]"; the curated re-cut, `Chipped_on_Bach_Preview_less_glitchy.mp4`, is 39,003,653 bytes (about 37.2 MiB) and runs 7 minutes and 28 seconds across exactly 4 tracks. Both sidecar text files end with an identical sentence confirming genuine hardware-accurate synthesis rather than a mockup: "All synthesis uses the NES Audio Processing Unit (2A03) via ReapNES JSFX."
