ANTIGRAVEMBLEMSIN3D

SCRATCH  C:\Dev\ANTIGRAVEMBLEMSIN3D · Vite, three.js, SQLite (Claudiens/ALCHEMYTIMELINEMAP/AlchemyBeatEmUp DBs)

ANTIGRAVEMBLEMSIN3D is confirmed not a git repository -- a full mirror of EMBLEMSIN3D's static files (verbatim copies of chiptune.js, gamesynths.js, jukebox and fugue pages, unchanged) rebuilt around a Vite toolchain (node_modules, dist/, and generated/ folders are all present, so it has been run locally at least once). Its own README frames it explicitly as a mirror for experiments that should not disturb the original project. Two genuinely new prototypes live here, both unrelated to the fugue engine: antigrav.html (three.js 'antigravity' visual explorations -- levitating apparatus, furnace-accident cascades, and a stated-but-not-visibly-implemented idea about fugue/orbit synchronization) and gameforge.html (a game-design idea generator pulling from three SQLite databases -- Claudiens, ALCHEMYTIMELINEMAP, AlchemyBeatEmUp -- with no audio component at all). No live URL, no deployment.

The Vite setup is a real, working local toolchain rather than a stub: `npm install && npm run dev` opens the project at `http://127.0.0.1:5193/antigrav.html` and a second entry point at `/gameforge.html`, and the project's own `node_modules` confirms Vite, three.js, Rolldown and LightningCSS are all actually installed, alongside a separate Python `requirements.txt` for a style-seed generation step (`npm run styles:seed`) that produces visual variety for the antigravity scenes. `antigrav.html` itself is described in the project's own notes as drawing on "four styles... plus sampled megabase game-design themes": levitating emblem apparatus, furnace-accident cascades, a stated but explicitly unimplemented idea about synchronizing fugue playback to orbital motion, and planetary board-puzzle concepts -- the orbit-synchronization idea remains, per the project's own admission, notes rather than working code. `gameforge.html` is confirmed genuinely SQLite-backed rather than using static or mocked data: it reads directly from three real project databases -- `Claudiens/db/atalanta.db`, `ALCHEMYTIMELINEMAP/db/alchemy_timeline.db`, and `AlchemyBeatEmUp/db/alchemical_images.db` -- extracting emblems, dictionary terms, timeline processes, bestiary monsters, lab furniture, materials, failure modes and cascade chains via its own `npm run gameforge:data` build step, functioning as a genuine cross-project idea-generation tool rather than a superficial mockup.

Because this fork is a full pre-Phase-5 mirror of EMBLEMSIN3D rather than a minimal two-file sandbox, it also carries a considerable amount of additional, unrelated content beyond the two named prototypes: a 213-model relief gallery (`gallery.html`, spanning the 51 Atalanta plates plus 162 woodcuts from the separate Hypnerotomachia material), the camera-driven `grandtour.html` cinematic tour, an `experiments.html` page holding several small alchemically-themed minigames (Regulated Fire, Solve et Coagula, a dragon-tail-biting mechanic), a per-emblem 3D diorama generator (`scene.html`), and a fully realized bespoke three.js courtyard environment for Emblem VIII specifically, built with toon shading and a Sobel-filter ink outline effect and interactive athanor/furnace elements. None of this additional content is a music or audio project in its own right -- it rode along because the fork copied the entire EMBLEMSIN3D tree rather than cherry-picking specific files -- but it means anyone considering reviving this fork for its two named audio-adjacent experiments would also be inheriting a genuinely substantial amount of unrelated visual-design work, not a clean, isolated two-prototype sandbox.

The practical upshot for anyone considering reviving this fork is a genuine trade-off rather than a simple "worth it" or "not worth it" call: the two audio-adjacent prototypes (antigrav.html's visual explorations and gameforge.html's cross-database idea generator) are both real, working, and distinctive enough to be worth resurrecting on their own merits, particularly gameforge.html's live SQLite querying across three separate alchemy-themed databases, which is a more substantial piece of cross-project integration work than its brief README description suggests. But recovering either one means either extracting just those two HTML files and their JS dependencies into a smaller, purpose-built sandbox, or accepting the full weight of the inherited EMBLEMSIN3D mirror (the 213-model gallery, the cinematic tour, the Emblem VIII courtyard, and the several unrelated minigames) that currently surrounds them. No document in the project states a preference between those two paths, so it remains an open decision rather than a next step already scoped.
